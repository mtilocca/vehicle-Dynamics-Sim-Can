## Architecture Overview

```
src/
  tls/
    tls_creds.hpp   — public API: tls_creds_init(), HDV_TLS_SERVER_TAG
    tls_creds.cpp   — loads cert + key via tls_credential_add()
  http/
    http_server.cpp — IPPROTO_TLS_1_2 socket on port 443
```

The server certificate and private key are embedded at build time as `.inc` files
(generated by `generate_inc_file_for_target()` in `CMakeLists.txt`). At runtime,
`tls_creds_init()` is called once from the HTTP server thread before any socket is
created. Credentials are registered into Zephyr's TLS credential store under
`HDV_TLS_SERVER_TAG = 1` and are available to all sockets in the process — both
the HTTPS server and any future MQTTS client.

### TLS socket setup

```cpp
int srv = zsock_socket(AF_INET, SOCK_STREAM, IPPROTO_TLS_1_2);

sec_tag_t sec_tag = HDV_TLS_SERVER_TAG;
zsock_setsockopt(srv, SOL_TLS, TLS_SEC_TAG_LIST, &sec_tag, sizeof(sec_tag));
// TLS role (server) is implicit: accept() = server, connect() = client.

zsock_bind(srv, ...);
zsock_listen(srv, 3);
int client = zsock_accept(srv, ...);  // TLS handshake happens HERE
```

**Key behaviour:** `zsock_accept()` in Zephyr TLS mode runs the full TLS handshake
synchronously inside `ztls_accept_ctx()`. If the handshake fails (bad cert, no shared
cipher, allocation failure), `accept()` returns `-1` with `errno` set to the mbedTLS
error code. There is no lazy handshake.

## Certificate

Self-signed RSA-2048, 10-year validity, IP SAN for browser compatibility:

```bash
openssl req -x509 -newkey rsa:2048 \
  -keyout zephyr/certs/server.key \
  -out    zephyr/certs/server.crt \
  -days 3650 -nodes \
  -subj "/CN=hdv-sim/O=HDV/C=AU" \
  -addext "subjectAltName=IP:192.168.1.80"
```

The IP SAN (`subjectAltName=IP:192.168.1.80`) allows Chrome and Firefox to accept the
certificate with a one-time "proceed anyway" exception rather than a hard block. Without
it, modern browsers reject IP-addressed TLS endpoints regardless of whether the cert is
trusted.

Both files are gitignored. Regenerate them if the board IP changes or the cert expires.

## Build-time cert embedding

`CMakeLists.txt` calls `generate_inc_file_for_target()` which invokes `file2hex.py` to
convert binary files to C hex literals:

```cmake
generate_inc_file_for_target(app
    ${CMAKE_CURRENT_SOURCE_DIR}/certs/server.crt
    ${CMAKE_CURRENT_BINARY_DIR}/server_cert.inc)

generate_inc_file_for_target(app
    ${CMAKE_CURRENT_SOURCE_DIR}/certs/server.key
    ${CMAKE_CURRENT_BINARY_DIR}/server_key.inc)
```

The output of `file2hex.py` is a comma-separated list of hex byte literals ending with
a **trailing comma and newline** (e.g. `0x0a,\n`). It does **not** append a null
terminator.

### The null-terminator requirement

`sockets_tls.c` detects PEM format with:

```c
static bool crt_is_pem(const void *buf, size_t buflen) {
    return (buflen != 0 && ((const char *)buf)[buflen - 1] == '\0' && ...);
}
```

Without `\0`, the cert falls through to DER parsing, which fails on PEM data.

The fix in `tls_creds.cpp`:

```cpp
// file2hex.py ends with a trailing comma+newline: "0x0a,\n"
// '\0' is placed WITHOUT a leading comma — the .inc trailing comma is the separator.
// sizeof() counts '\0', giving the correct length for tls_credential_add().
static const unsigned char server_cert[] = {
#include "server_cert.inc"
'\0'
};
static const unsigned char server_key[] = {
#include "server_key.inc"
'\0'
};
```

Do NOT write `, '\0'` — the `.inc` file already ends with a comma, so a double comma
(`0x0a,,'\0'`) is a C syntax error.

## Required Kconfig symbols

Every symbol below is **required**. Omitting any one of them caused a handshake failure.

### TLS socket layer

```conf
CONFIG_NET_SOCKETS_SOCKOPT_TLS=y
```
Enables the `IPPROTO_TLS_1_2` socket protocol and pulls in `TLS_CREDENTIALS` and
`MBEDTLS_BUILTIN`. Without this there is no TLS socket type.

```conf
CONFIG_MBEDTLS_BUILTIN=y
```
Selects Zephyr's bundled mbedTLS. Required for `MBEDTLS_MEMORY_BUFFER_ALLOC_C` (see below).

### mbedTLS dedicated heap — the most important one

```conf
CONFIG_MBEDTLS_ENABLE_HEAP=y
CONFIG_MBEDTLS_HEAP_SIZE=65536
```

`config-tls-generic.h` (the mbedTLS config used by `MBEDTLS_BUILTIN=y`) defines
`MBEDTLS_MEMORY_BUFFER_ALLOC_C`. This **replaces** `malloc`/`free` with an internal
buffer allocator that must be explicitly initialised with
`mbedtls_memory_buffer_alloc_init()`.

Zephyr calls that initialiser only when `CONFIG_MBEDTLS_ENABLE_HEAP=y`:

```c
// zephyr/modules/mbedtls/zephyr_init.c lines 46-48
#if defined(CONFIG_MBEDTLS_ENABLE_HEAP) && defined(MBEDTLS_MEMORY_BUFFER_ALLOC_C)
    mbedtls_memory_buffer_alloc_init(_mbedtls_heap, sizeof(_mbedtls_heap));
#else
    #define init_heap(...)   // expands to nothing
#endif
```

Without `ENABLE_HEAP=y`, `init_heap()` expands to nothing. Every `mbedtls_malloc()`
returns NULL. The handshake aborts before ServerHello — silently, because the failure
happens inside the TLS socket recv path which returns an error that `read_request_line`
swallows.

**Heap sizing:** 65536 bytes (64 KB). This covers:
- 2 × 4096 B TLS I/O buffers
- RSA-2048 bignum operations (~20 KB)
- X.509 certificate parsing (~8 KB)
- Handshake state machine overhead

This heap is **separate** from `CONFIG_HEAP_MEM_POOL_SIZE` (the general Zephyr heap).
Both must be sized. The mbedTLS heap is only allocated during the handshake; it is
returned to the pool after the session is established.

### PEM certificate format

```conf
CONFIG_MBEDTLS_PEM_CERTIFICATE_FORMAT=y
```

Without this, Zephyr's mbedTLS is compiled without `MBEDTLS_PEM_PARSE_C` and
`MBEDTLS_BASE64_C`. It can only parse DER (binary) certificates. Passing a PEM cert
to `tls_credential_add()` returns `EINVAL` during `tls_mbedtls_init`, causing
`accept()` to fail with `errno=22`.

### Cipher suite

```conf
CONFIG_MBEDTLS_KEY_EXCHANGE_ECDHE_RSA_ENABLED=y
```
The key-exchange mechanism. Has **no `default y`** — it must be set explicitly.
Without it, mbedTLS has no cipher suite that can authenticate with an RSA certificate.

```conf
CONFIG_MBEDTLS_ECDH_C=y
CONFIG_MBEDTLS_ECP_C=y
CONFIG_MBEDTLS_ECP_DP_SECP256R1_ENABLED=y
```
ECDHE depends on ECDH, which depends on ECP. The curve (prime256v1 / P-256) must also
be explicitly enabled. The server ephemeral key uses P-256 even though the cert is
RSA-2048 — these are independent.

```conf
CONFIG_MBEDTLS_CIPHER_AES_ENABLED=y
CONFIG_MBEDTLS_CIPHER_GCM_ENABLED=y
```
AES-128-GCM bulk cipher. Symbol name is `MBEDTLS_CIPHER_GCM_ENABLED`
(NOT `MBEDTLS_GCM_ENABLED` — that symbol does not exist).

```conf
CONFIG_MBEDTLS_SHA256=y
```
PRF/MAC. Symbol name is `MBEDTLS_SHA256` (no `_ENABLED` suffix).
It has a `default y` but is listed explicitly for documentation clarity.

### Record buffer and contexts

```conf
CONFIG_MBEDTLS_SSL_MAX_CONTENT_LEN=4096
CONFIG_NET_SOCKETS_TLS_MAX_CONTEXTS=2
```
4096 B record buffer is sufficient for the dashboard page (largest response).
Two TLS contexts: one HTTPS + one reserved for future MQTTS.

## Kconfig pitfalls

### Inline comments are NOT supported

```conf
# WRONG — "#" becomes part of the value, causing "undefined symbol" errors
CONFIG_MBEDTLS_CIPHER_AES_ENABLED=y   # AES encryption

# CORRECT — comment on its own line
# AES encryption
CONFIG_MBEDTLS_CIPHER_AES_ENABLED=y
```

### Auto-derived symbols cannot be set directly

```conf
# WRONG — MBEDTLS_DEBUG_LEVEL is auto-computed from a choice, has no prompt
CONFIG_MBEDTLS_DEBUG_LEVEL=1

# CORRECT — set the choice symbol; the int is auto-derived
CONFIG_MBEDTLS_LOG_LEVEL_ERR=y
```

### Wrong symbol names (common mistakes)

| Wrong | Correct |
|-------|---------|
| `CONFIG_MBEDTLS_GCM_ENABLED` | `CONFIG_MBEDTLS_CIPHER_GCM_ENABLED` |
| `CONFIG_MBEDTLS_SHA256_ENABLED` | `CONFIG_MBEDTLS_SHA256` |
| `CONFIG_MBEDTLS_LOG_LEVEL=4` | `CONFIG_MBEDTLS_LOG_LEVEL_DBG=y` (choice) |

## Diagnostic technique

Adding `errno` to the `accept()` failure log was the key diagnostic:

```cpp
int client = zsock_accept(srv, (struct sockaddr*)&client_addr, &client_len);
if (client < 0) {
    LOG_ERR("HTTPS: accept() failed (errno=%d) — TLS handshake likely failed", errno);
    k_msleep(10); continue;
}
LOG_INF("HTTPS: client connected (TLS handshake OK), fd=%d", client);
```

`errno=22` (EINVAL) → cert/key parsing failed (missing PEM support or bad format)  
`errno=12` (ENOMEM) → mbedTLS heap not initialised  
`errno=0` + 0 bytes → handshake silently failed (missing cipher suite or heap = NULL)

The UART log `accept() failed (errno=22)` immediately pointed to `tls_add_own_cert`
failing inside `tls_mbedtls_init`.

## Debugging history — bugs fixed in order

Each of these produced silent or misleading failures; all were fixed before HTTPS worked:

| # | Symptom | Root cause | Fix |
|---|---------|------------|-----|
| 1 | `accept()` returns -1, errno=0, 0 bytes to client | No cipher suite enabled — `MBEDTLS_KEY_EXCHANGE_ECDHE_RSA_ENABLED` has no `default y` | Add cipher suite + dependencies to `prj.conf` |
| 2 | Same | mbedTLS heap never initialised — `MBEDTLS_MEMORY_BUFFER_ALLOC_C` active but `init_heap()` is a no-op | Add `CONFIG_MBEDTLS_ENABLE_HEAP=y` + `HEAP_SIZE` |
| 3 | `accept()` errno=22 (EINVAL) | `MBEDTLS_PEM_PARSE_C` not compiled in — cert/key parsing returns EINVAL on PEM input | Add `CONFIG_MBEDTLS_PEM_CERTIFICATE_FORMAT=y` |
| 4 | Compilation error: `expected primary-expression before ','` | `tls_creds.cpp` used `, '\0'` — `.inc` already ends with comma, producing double comma | Change to just `'\0'` (no leading comma) |
| 5 | Kconfig error: `MBEDTLS_GCM_ENABLED` undefined | Wrong symbol name | Rename to `MBEDTLS_CIPHER_GCM_ENABLED` |
| 6 | Kconfig error: `MBEDTLS_SHA256_ENABLED` undefined | Wrong symbol name | Rename to `MBEDTLS_SHA256` |
| 7 | Kconfig error: `MBEDTLS_LOG_LEVEL` not settable | Auto-derived from choice | Remove; use `MBEDTLS_LOG_LEVEL_ERR=y` if needed |
| 8 | Kconfig error: `MBEDTLS_DEBUG_LEVEL` not settable | Auto-derived int | Remove |
| 9 | Build re-uses old Kconfig after fix | West incremental build cached old config | `rm -rf build` before each Kconfig change |

## Memory impact

| Item | Size |
|------|------|
| mbedTLS heap (`MBEDTLS_HEAP_SIZE`) | 64 KB (dedicated, separate from system heap) |
| HTTP server thread stack | 16 KB (up from 8 KB — TLS handshake needs ~12 KB headroom) |
| TLS I/O record buffer | 4 KB × 2 (in/out, inside mbedTLS heap) |
| cert + key in flash | ~3 KB (1205 + 1705 bytes) |

The mbedTLS heap is drawn from `CONFIG_HEAP_MEM_POOL_SIZE` during the handshake and
released after. Net steady-state overhead is zero beyond the 16 KB stack increase.

## Future: MQTTS reuse

```cpp
// mqtt_client.cpp
#include "tls_creds.hpp"

int sock = zsock_socket(AF_INET, SOCK_STREAM, IPPROTO_TLS_1_2);
sec_tag_t tag = HDV_TLS_SERVER_TAG;
zsock_setsockopt(sock, SOL_TLS, TLS_SEC_TAG_LIST, &tag, sizeof(tag));
// connect() → then use Zephyr MQTT lib over TLS socket
```

`tls_creds_init()` is called once at startup (inside the HTTP thread). The credentials
are available globally to any TLS socket. `HDV_TLS_CA_TAG = 2` is reserved for a CA
certificate when connecting to an external MQTTS broker.

## Phase 4 — Before enabling RDP Level 1

`root-rsa-2048.pem` is MCUboot's **public test key**, committed to the MCUboot GitHub
repository. Anyone can use it to sign a valid image for this board. Before enabling
RDP Level 1:

1. Generate a project-specific RSA-2048 signing key:
   ```bash
   python3 $ZEPHYR_BASE/../bootloader/mcuboot/scripts/imgtool.py keygen \
     -k zephyr/mcuboot_rsa2048_project.pem -t rsa-2048
   ```
2. Set `SB_CONFIG_BOOT_SIGNATURE_KEY_FILE` in `zephyr/sysbuild.conf`.
3. Rebuild both MCUboot + app with pristine sysbuild.
4. Flash both.
5. Keep the `.pem` gitignored — back it up offline.

See [docs/mcuboot_signing_and_flash_recovery.md](mcuboot_signing_and_flash_recovery.md)
for full details.
